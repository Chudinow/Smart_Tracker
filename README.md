# Smart Tracker (Work Life Balance)

Веб-приложение для трекинга привычек и настроения: отмечай выполнение привычек (чекбоксы и счётчики), смотри ленту по дням в календаре и аналитику за 7/30/90 дней (включая график настроения).

---

## Возможности

- ✅ Регистрация и вход пользователя (сессии)
- ✅ Привычки:
  - **checkbox** (выполнено/не выполнено)
  - **counter** (например, “вода 0/3”)
- ✅ Главная страница “Мой день” — список привычек на сегодня, логирование выполнения
- ✅ “Лента” (календарь) — обзор месяца:
  - прогрессбар = % выполнения за день
  - иконки: настроение / заметка / предупреждение о пропусках
  - просмотр выбранного дня справа
- ✅ “Аналитика”:
  - вкладки Stats / Habits / Mood
  - SVG-график настроения (с разрывами, тултипы по точкам)
  - сводные KPI за период

## Технологии (стек)

**Backend**
- Python
- FastAPI (ASGI)
- Starlette Sessions (cookie-based session)
- SQLAlchemy ORM
- SQLite (по умолчанию)

**Frontend**
- Jinja2 templates (server-side rendering)
- CSS (стили в одном файле)
- Немного JS точечно (например, тултип графика на SVG)

## Как это работает (в двух словах)

- Роуты в `app/ui/main.py` отрисовывают страницы через `Jinja2Templates`.
- Данные и вычисления берутся из `app/db/repo.py`.
- База описана моделями SQLAlchemy в `app/db/models.py`.
- Страницы — это HTML-шаблоны (Jinja), поэтому “фронт” по сути генерируется сервером.
- Прогрессбар и иконки в календаре — **это не JS**, это результат бэкенд-расчётов, прокинутых в шаблон.

## Асинхронность: где она тут и зачем

FastAPI запускается на ASGI-сервере (обычно `uvicorn`) и внутри использует `asyncio` для обслуживания запросов.

При этом:
- даже если у тебя много “обычных” (`def`) обработчиков — сервер всё равно работает в async-окружении;
- сейчас работа с БД через SQLAlchemy Session (sync), поэтому запросы выполняются синхронно (обычный подход для MVP).

То, что ты видишь в трассировках `asyncio.run(...)` — это внутренняя “машина” uvicorn/ASGI, а не обязательно твой код.

## Установка и запуск (локально)

### 1) Требования
Рекомендую Python **3.11 / 3.12**.

> На Python 3.13 у некоторых версий SQLAlchemy могут быть странные ошибки типизации. Если видишь ошибки уровня `TypingOnly` — почти всегда лечится переходом на 3.12 или обновлением зависимостей.
